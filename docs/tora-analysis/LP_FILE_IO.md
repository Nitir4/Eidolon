# Foundation 4 LP document and file boundary

## Purpose and scope

Open existing TORA LP inputs, preserve their stored precision and settings,
edit the value-owned document and write a file that TORA can open. This library
is independent of Qt. Native dialogs and the input-grid/controller binding
belong to the first Phase 2 module. This gate implements no solver or fabricated
solution and does not enable the preview's file commands.

## Observed format and provenance

The field-by-field grammar is in [FILE_FORMAT.md](../FILE_FORMAT.md).
`tests/fixtures/tora-file-settings.tsv` records N, D, notation, byte count,
SHA-256 and private capture path for each of 27 actual TORA saves: 15 corpus
round trips, four field/precision probes, two UI-created notation defaults,
four focused text saves and two new clone-to-TORA bridge saves.
These files and the completed corpus were reused, not rerun. The independent
model transcription is `tests/fixtures/lp-models.txt`; fresh-model defaults are
transcribed separately in the round-trip test. CI assembles those original
transcriptions and compares their generated byte hashes with TORA's saved
hashes. It does not receive raw proprietary files or screenshots.

Private local verification additionally opens the actual saved bytes, compares
them with the independent transcription, parses them and requires exact
re-serialization. Every variable alias, coefficient, relation, RHS, bound,
flag and header setting is compared in order. No numerical formatter is used
to infer or round input values. Infeasible/unbounded inputs and reversed bounds
can be saved; solver/input validity is a separate operation.

## Document lifecycle

`LpDocument` owns a model and input number-format settings. It retains the
original ordered records and a saved semantic checkpoint. Creation is dirty
and has no filename. Decode/open is clean. Editing any model field or format
setting makes it dirty; restoring the saved values makes it clean again.
Signed zero changes are distinguished. Save checkpoints only after successful
file replacement. Save As changes the source path and makes the new copy
editable. The selected read-only open mode permits in-memory edits.

The observed read-only path opens the grid, allows title edits and leaves
Save/Save As enabled. Save displays the native Save As picker rather than
immediately changing the original file; editable Save also uses this picker.
Save As writes an edited copy. `FileErrorCode::ReadOnly` is a controller
redirect signal, not a claimed TORA dialog. Likewise, MissingFilename asks the
later controller to open its picker. File selection, suffix defaults, overwrite
confirmation and cancellation are UI responsibilities; the store uses the
exact path supplied to it.

## Parsing and preservation

The reader bounds byte allocation at 4 MiB, checks CRLF framing, marker, header,
dimensions and required grid record count before constructing the model. It
requires quoted cells, recognized direction/relation/sign tokens and finite
numerical cells; positive `infinity` is recognized only in upper bounds.
Numerical parsing uses `from_chars`, independent of OS locale. It accepts
ASCII space/tab around numeric/relation cells and an optional positive sign.
Counts/settings are strict unquoted integers. The observed Student dimensions
are 1..100; the existing formatter's supported engineering precision envelope
is now decimal N=1..99 / scientific N=0..99 and D=0..99 after focused Phase 2
11/99 observations. Exact legacy extrema remain unknown. These bounds and the byte
limit are explicitly not a claim about every legacy file or TORA's N/D limits.

Unchanged fields reuse original record spellings, including numeric strings,
relation padding, sign flags and aliases. Non-constraint relation/RHS cells
are preserved opaquely. Extra records are retained. When dimensions change,
nonempty unknown reserved cells block serialization rather than being lost;
ordinary empty reserved cells can be rebuilt. Changed finite values use the
shortest binary64 round-trip `to_chars` spelling. Fresh positive zero follows
the observed mode defaults; negative zero retains its sign. Display settings
never round stored coefficients.

## Approved recovery and diagnostics

TORA saved the title `F4, "quoted" cafe` as a quoted record with doubled interior
quotes. Reopening its own file displayed title `F4,`, zero variables and zero
constraints. That capture records a legacy reader failure, not a successful
round trip. The user explicitly chose **Recover the saved data** on 2026-10-07.
The clone therefore decodes doubled quotes, restores the title and full model,
and preserves the original bytes. This is an approved compatibility exception.
An explicit Reject policy is available. Unpaired quotes remain errors. A quoted
variable-name probe is separate; the first combined text attempt reinitialized
the grid and does not prove that alias was saved.

Marker 9999 uses the captured `Open FileSave As Warning` title and exact message,
including TORA's spelling `elected`. Other failures are typed engineering
diagnostics with one-based record locations where available. The clone rejects
LF-only/truncated/nonfinite/invalid-shape inputs without producing the partially
blank or corrupt models seen in the specific legacy malformed-file captures.
It does not invent TORA error wording for these safety checks.

## Filesystem operations

Binary streams preserve CRLF across OSes. Paths use `std::filesystem::path`,
including native Unicode paths. The store encodes and allocates its replacement
checkpoint before writing. An exclusively created sibling temporary prevents
concurrent temporary-file reuse; complete writes are flushed and closed, then
replaced with POSIX rename or Windows `MoveFileExW`. Failure removes only that
operation's temporary file and preserves the old file/path/checkpoint. Tests
exercise replacement failure, invalid serialization, read-only copying and
coefficient precision. The operation provides atomic visibility on supported
local filesystems; it does not claim power-loss recovery or preserve all custom
ACL/metadata on an existing destination. No OS-specific numerical path exists.

## Live bridge and unknowns

The live bridge uses clone-written named/finite-bound, changed high-precision
and fresh scientific files, then asks TORA to Save As and reopen them. Reviewed
capture results are recorded in [FOUNDATION4_REPORT.md](../FOUNDATION4_REPORT.md).
Automation launches/reuses TORA first, validates the reference window, observes
its native controls and saves screenshots/bytes. It neither inspects binaries
nor extracts resources. Failed capture attempts are not counted as verified.

The observed non-ASCII title `F4 cafe é` stores byte E9 in the Windows-1252
reference environment and reopens correctly. The low-level document/model text
fields at this compatibility boundary preserve legacy bytes opaquely, including
E9; they do not normalize to UTF-8. Native presenters must decode/encode those
fields using the selected legacy code page. File framing contains no encoding
marker; automatic detection of arbitrary code pages is not claimed. Unicode
filesystem paths are supported independently.

The native Text picker appends `.txt` when the entered filename has no suffix;
the store itself receives and uses the exact resulting path. Subsequent Save
opens a picker prefilled with the latest Save As target; confirming replacement
updates that target and leaves the original source unchanged. The legacy caption
remains the original source. Confirmation/cancel behavior belongs to the native
controller rather than the store's direct-save convenience function.
No in the overwrite prompt returns to the picker; cancelling it preserves the
existing bytes. A later Save As can save the edited model to another destination.
Quoted-alias entry could not be committed by the observed grid workflow; this
is an input-editor question for Phase 2, not a verified saved-alias capture.
Arbitrary corrupted files, other Windows code pages, numerical
entry grammar, all N/D extrema and physical printing remain unknown unless
explicitly resolved in FILE_BEHAVIOR.md. The remaining input/solver observations
stay assigned to their own module gates.
